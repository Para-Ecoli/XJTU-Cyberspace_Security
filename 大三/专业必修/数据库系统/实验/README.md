请忽视报告末尾关于使用 MySQL 进行实验的建议，因为 MySQL 对 ACID 原则的支持并不完整。

可以了解一下 [MySQL 的 11472 号 bug](https://bugs.mysql.com/bug.php?id=11472)，这个 bug 的核心问题是：当通过外键的级联操作间接更新或删除数据时，目标表上关联的触发器不会被执行，这意味着 MySQL 中 trigger 的触发是没有保障的。

最令人不解的是，这个编号为 11472 的 Bug 最早在 2005 年 6 月被提交，距今已经超过 20 年，但官方依然没有给出实质性的修复方案。虽然 MySQL 官方团队早在 2005 年就承诺会在 5.1 版本中修复，但后来食言了。目前，官方仅仅是将这个缺陷作为一条“已知限制”写进了官方手册里，明确标注为“级联外键操作不会激活触发器”。换句话说，官方已经把它当成一个 Feature 而非需要紧急修复的 Bug 来处理了（欢迎加入 Mojang）。由于拖延时间实在太久，开发者社区里甚至出现了给这个 Bug “过生日”的现象。还有开发者无奈地表示，这个 Bug 的年龄比自己的年龄都大。

正是因为这个长期悬而未决的严重缺陷，很多对数据完整性有极高要求的团队最终选择放弃 MySQL，转而投向了 PostgreSQL 等数据库。这也是为什么现在许多大厂和资深架构师在制定 MySQL 开发规范时，会明确禁止同时使用外键和触发器，甚至直接建议在应用层完全抛弃外键的根本原因。
